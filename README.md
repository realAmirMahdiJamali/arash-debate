# ARASH Debate

سامانه فارسی و راست‌چین مدیریت مناظره با رابط میزبانی‌شده روی GitHub Pages و احراز هویت، پایگاه داده، کنترل دسترسی و همگام‌سازی زنده روی Supabase.

## تنظیمات قطعی این نسخه

- امتیازدهی تیمی و فردی به‌صورت مستقل
- پنج حساب داوری فعال؛ مدیر در شمار داوران نیست و فرم داوری ندارد
- امتیاز فردی هر شرکت‌کننده از ۰ تا ۱۰ با دقت ۰٫۱؛ میانگین نهایی از پنج داور
- امتیاز تیمی از ۱۰۰ بر اساس شش معیار موجود در سامانه قبلی
- نقش‌های قابل تعریف توسط مدیر؛ نقش‌های سیستمی مدیر و داور برای کنترل دسترسی محفوظ‌اند
- مدیریت حساب‌ها: ایجاد، ویرایش نام کاربری، نام نمایشی، نقش، گذرواژه و فعال/غیرفعال‌سازی یا حذف
- ایجاد دوره، گروه و اعضا؛ تعریف عنوان نقش هر عضو در مناظره
- انتشار عمومی نتایج پس از تکمیل امتیازهای هر پنج داور
- نام کاربری به بزرگی و کوچکی حروف حساس است و در تابع امن ورود دقیقاً تطبیق داده می‌شود

## راه‌اندازی عملیاتی

### ۱. ایجاد پروژه Supabase

یک پروژه جدید بسازید. در SQL Editor کل فایل `supabase/schema.sql` را یک‌بار اجرا کنید. این اسکریپت جداول، سیاست‌های RLS، نقش‌ها، همگام‌سازی Realtime و تابع کنترل انتشار نتایج را ایجاد می‌کند.

### ۲. ساخت اولین حساب مدیر

در Supabase Dashboard به Authentication → Users بروید و یک کاربر جدید با ایمیل داخلی دلخواه (مثلاً `arash-admin@your-domain.invalid`) بسازید؛ گزینه تأیید ایمیل را فعال کنید و یک گذرواژه قوی و تازه قرار دهید. شناسه UUID کاربر را کپی کنید.

سپس در SQL Editor، به‌جای مقادیر نمونه، UUID و نام کاربری مدیر خود را وارد و اجرا کنید:

```sql
insert into public.user_profiles(id, username, display_name, role_key, active)
values ('UUID-OF-AUTH-USER', 'AdminUsername', 'مدیر سامانه', 'admin', true);
```

نام کاربری دقیقاً با همان حروفی که اینجا ثبت می‌کنید پذیرفته می‌شود. ورود از طریق تابع امن انجام می‌شود و ابتدا نام کاربری را با تطبیق حساس به حروف پیدا می‌کند، سپس گذرواژه را با Supabase Auth اعتبارسنجی می‌کند.

### ۳. انتشار Edge Function

از ریشه پوشه پروژه:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy admin-users
```

تابع از متغیرهای امن Supabase استفاده می‌کند. کلید `service_role` فقط در محیط سرور Supabase باقی می‌ماند و نباید در GitHub، `config.js` یا کد مرورگر قرار گیرد.

### ۴. اتصال رابط کاربری

در `config.js` این مقادیر را وارد کنید:

```js
window.AMJ_CONFIG = {
  supabaseUrl: "https://YOUR-PROJECT.supabase.co",
  supabaseAnonKey: "YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY",
  demoMode: false
};
```

کلید anon یا publishable برای قرارگرفتن در رابط عمومی طراحی شده است؛ امنیت داده‌ها باید با RLS تأمین شود. هرگز کلید service role را اینجا نگذارید.

### ۵. انتشار GitHub Pages

تمام فایل‌ها و پوشه‌های این پروژه را در ریشه repository قرار دهید؛ به‌طوری‌که `index.html` در ریشه باشد. سپس در Settings → Pages، انتشار از شاخه `main` و پوشه `/root` را فعال کنید.

## ساختار امتیازدهی

### تیمی

| معیار | سقف |
|---|---:|
| کیفیت استدلال و تفکر انتقادی | ۳۰ |
| پاسخگویی به استدلال‌های مخالف | ۲۵ |
| قدرت بیان و متقاعدسازی | ۱۵ |
| انسجام و سازماندهی سخنرانی | ۱۰ |
| همکاری و هماهنگی تیمی | ۱۰ |
| مدیریت زمان و رعایت قوانین | ۱۰ |
| **مجموع** | **۱۰۰** |

میانگین تیم برابر میانگین مجموع امتیازهای پنج داور است.

### فردی

هر داور برای هر عضو یک امتیاز بین ۰ تا ۱۰ با گام ۰٫۱ ثبت می‌کند. امتیاز نهایی فرد برابر مجموع پنج امتیاز تقسیم بر پنج است. انتشار نتایج تا زمانی که هر پنج داور برای تمام گروه‌ها و اعضای دوره امتیاز ثبت نکرده باشند، از سمت پایگاه داده رد می‌شود.

## مدیریت نقش و حساب

- مدیر می‌تواند عنوان نقش جدید تعریف کند و آن را هنگام ساخت یا ویرایش حساب به کاربر اختصاص دهد.
- نقش‌های سیستمی `admin` و `judge` برای کنترل دسترسی محفوظ‌اند.
- تنها حساب‌های دارای نقش سیستمی `judge` در سقف پنج داور و محاسبه میانگین شرکت می‌کنند.
- مدیر یک حساب مدیریتی جداگانه است و هیچ امتیازی به نام او ثبت نمی‌شود.
- غیرفعال‌سازی حساب مانع ورود می‌شود. قبل از انتشار، باید پنج حساب داوری فعال وجود داشته باشد.

## پیش‌نمایش

برای نمایش آزمایشی بدون Supabase، `demoMode: true` بگذارید یا تنظیمات Supabase را خالی نگه دارید. حالت پیش‌نمایش از `localStorage` همان مرورگر استفاده می‌کند؛ داده‌های آن بین کاربران و دستگاه‌ها همگام نمی‌شوند و برای استفاده واقعی مناسب نیست.

## امنیت و محدودیت‌ها

- فایل‌های GitHub Pages عمومی‌اند؛ گذرواژه یا کلید محرمانه را در آن‌ها قرار ندهید.
- پس از تغییر نقش یک کاربر به `judge`، ظرفیت پنج داور کنترل می‌شود. حساب‌های داوری را از پنل مدیر مدیریت کنید.
- نام کاربری از طریق Edge Function و به‌صورت دقیق (case-sensitive) بررسی می‌شود؛ ایمیل داخلی Supabase در رابط کاربری نمایش داده نمی‌شود.
- برای ورود واقعی، SQL باید اجرا شده باشد، Edge Function باید deploy شده باشد و `config.js` باید مقادیر صحیح داشته باشد.
- پیش از انتشار عمومی، با حساب مدیر و پنج حساب داور آزمایشی، ایجاد دوره، ثبت گروه و اعضا، ثبت هر دو نوع امتیاز و انتشار را تست کنید.
