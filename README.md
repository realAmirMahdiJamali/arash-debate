# ARASH Debate

سامانه فارسی و راست‌چین مدیریت مناظره‌های کلاسی؛ رابط کاربری روی GitHub Pages و سرویس احراز هویت، پایگاه داده و همگام‌سازی زنده روی Supabase اجرا می‌شود.

## امکانات

- صفحه عمومی آخرین دوره، جدول نتایج رسمی، آرشیو جست‌وجوپذیر و نظرسنجی مخاطبان
- پنل مدیر برای مدیریت دوره‌ها، تیم‌ها، حساب‌ها، فعال‌سازی نظرسنجی و انتشار نتایج
- پنل پنج داور برای ثبت شش معیار امتیازدهی و یادداشت‌های مستقل در هر معیار؛ یادداشت‌ها برای سایر داوران و بازدیدکنندگان نیز همگام و قابل مشاهده‌اند
- پنل چهار گروه مشاهده‌گر برای ثبت نقطه قوت، ضعف مشخص و پیشنهاد بهبود
- محاسبه میانگین امتیاز پنج داور برای هر تیم و تعیین رتبه با ترتیب تساوی کیفیت استدلال و سپس پاسخگویی
- همگام‌سازی تغییرات با Supabase Realtime
- حالت پیش‌نمایش محلی برای آزمایش رابط کاربری بدون تنظیم سرویس خارجی

## پیش‌نمایش محلی

فایل `index.html` را باز کنید. در `config.js` مقدار `demoMode` به‌صورت پیش‌فرض `true` است. با دکمه ورود، نقش `admin` یا `judge` یا `observer` را برای آزمایش انتخاب کنید. در حالت محلی داده‌ها در localStorage همان مرورگر ذخیره می‌شوند و بین دستگاه‌ها یا کاربران همگام نمی‌شوند.

## راه‌اندازی نسخه عملیاتی

### ۱. ساخت پروژه Supabase

یک پروژه جدید در Supabase بسازید. سپس محتوای `supabase/schema.sql` را در SQL Editor اجرا کنید.

### ۲. ساخت حساب مدیر

در Supabase Dashboard از بخش Authentication یک کاربر بسازید:

- Email: `40418213@users.arashgroup.invalid`
- Password: گذرواژه مدیر را در همان داشبورد تعیین کنید.
- Email confirmed: فعال
- User metadata:

```json
{
  "student_id": "40418213",
  "role": "admin",
  "force_password_change": false
}
```

پروفایل مدیر به‌صورت خودکار با trigger ایجاد می‌شود. گذرواژه واقعی مدیر در هیچ‌یک از فایل‌های عمومی پروژه قرار نمی‌گیرد.

### ۳. پیکربندی رابط کاربری

در `config.js` مقدارهای پروژه را وارد کنید:

- `supabaseUrl`: Project URL
- `supabaseAnonKey`: کلید anon یا publishable پروژه
- `demoMode`: مقدار `false`

کلید service role را هرگز در `config.js` یا هیچ فایل سمت مرورگر قرار ندهید.

### ۴. انتشار تابع امن ساخت حساب

Supabase CLI را نصب و وارد حساب شوید، سپس از ریشه پروژه اجرا کنید:

```bash
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy admin-users
```

تابع از متغیرهای امن محیط Supabase استفاده می‌کند. کلید service role فقط در محیط تابع باقی می‌ماند. تابع فقط مدیر واردشده را مجاز به ساخت حساب داور و مشاهده‌گر می‌کند.

### ۵. انتشار روی GitHub Pages

تمام محتویات پوشه `arash-debate` را در ریشه repository قرار دهید. در تنظیمات repository، بخش Pages را باز کنید و انتشار از شاخه اصلی و پوشه `/root` را فعال کنید. فایل `index.html` باید در ریشه منتشرشده باشد.

## ایجاد حساب داور و مشاهده‌گر

مدیر پس از ورود از بخش «حساب‌ها» شماره دانشجویی، نقش، کد ملی به‌عنوان گذرواژه اولیه و در صورت نیاز شماره گروه مشاهده‌گر را ثبت می‌کند. کد ملی فقط به Auth برای ساخت گذرواژه اولیه ارسال می‌شود و در جدول‌های عمومی برنامه ذخیره نمی‌شود. حساب داور در اولین ورود ملزم به تغییر گذرواژه است.

برای پنج داور، پنج حساب مستقل بسازید؛ در صورت داوری مدیر، چهار حساب داوری مستقل کافی است. مدیر می‌تواند از تب «فرم داوری من» با همان حساب مدیریتی خود نیز امتیاز ثبت کند. اگر مدیر هم یکی از پنج داور باشد، فقط چهار حساب داوری دیگر ایجاد کنید؛ اگر مدیر داوری نمی‌کند، پنج حساب داوری مستقل بسازید.

## منطق نهایی‌سازی

برای هر چهار تیم باید پنج فرم کامل وجود داشته باشد. تابع دیتابیس پس از کنترل تعداد فرم‌ها، میانگین هر معیار و میانگین کل را محاسبه می‌کند. رتبه‌بندی بر اساس میانگین کل، سپس کیفیت استدلال و سپس پاسخگویی انجام می‌شود. نتایج رسمی در جدول جداگانه منتشر می‌شوند.

## نظرسنجی عمومی

رأی مخاطبان در جدول مجزا ثبت می‌شود و در امتیاز رسمی داوران دخالت ندارد. هر مرورگر برای هر دوره یک شناسه رأی محلی نگه می‌دارد و محدودیت یکتایی سمت پایگاه داده نیز فعال است. این روش برای جلوگیری از رأی تکراری معمولی مناسب است، اما جایگزین احراز هویت رأی‌دهندگان یا سامانه ضدتقلب مبتنی بر هویت نیست.

## نکات امنیتی و عملیاتی

- فایل‌های GitHub Pages عمومی‌اند؛ هیچ گذرواژه، کلید service role یا اطلاعات محرمانه در آن‌ها قرار ندهید.
- کلید anon قابل انتشار است، به شرط آنکه RLS و سیاست‌های SQL فعال باشند.
- برای محیط عملیاتی، از گذرواژه‌های قوی و محرمانه استفاده کنید.
- همگام‌سازی زنده امتیازات، یادداشت‌های هر معیار، بازخورد گروه‌ها و نظرسنجی فقط پس از اتصال Supabase فعال می‌شود.
- در پیش‌نمایش محلی، نقش‌ها و داده‌ها صرفاً آزمایشی‌اند و امنیت یا همگام‌سازی بین کاربران واقعی ندارند.
